# Prompt: feature freeze and final demo

Read `docs/DEMO.md`, judging rubric and current deployed state. Stop proposing new nonessential features. Inspect the app as a judge would: can a first-time user understand it, does the main journey work, is the UI polished on phone and desktop, can it handle failure? Fix only blockers and serious regressions, with normal review gates.

Verify from actual evidence: production build, deployed URL, demo data, API credentials, backup recording, README, clean git state, attribution and official submission format. Write a 2–3 minute pitch and a judge Q&A cheat sheet. Never fabricate metrics or demo results. Announce the remaining risks plainly.
